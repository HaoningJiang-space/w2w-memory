# 原生服务匹配的静态驻留诊断

2026-10-08。在读取本次新结果前冻结。动机来自已归档HBM2单对象pilot的原生预算：
每memory一个32GB/s通道，原B的home与shared出口能力均高于该原生预算。
因此在该原生组织下，两颗memory原生工作量均衡的λ=1/2可能比原λ=8/13更合适。
这不是通用比例结论，也不改变cohort实验或训练owner。

仅两次HBM2命令回放，固定原pilot的完整对象、全部128个常驻专家、owner、N192、RX2、
request/native/link=1/0/1、B的256/160/160位宽、D1/D2、静态方向和几何。
第一个对照重放原B；第二个使用相同pair支持的1/2驻留，静态仲裁配额随布局合法重建。
通道、时序、控制器、桥接二进制必须与旧pilot一致。原子字32-byte，读取589,968字。
仅布局及静态配额改变，不把更短配额表报告成新增面积收益。

预测：若home原生通道是瓶颈，原B约需(8/13)倍单memory读时长；均衡布局约需1/2，
潜在时间比为13/16（约减少18.75%），但行状态、尾部和队列可造成偏差。
这是条件预测，不写为尚未执行的结果。两次回放不新增HBM/native硬件，跨原生profile
不比较speedup，也不外推到完整多任务batch。

检查全对象、逻辑trace一致，endpoint/geometry/exposure一致，32-bank原生计数、
控制器accept/serve、逐路字节与最终pending守恒；旧B重放必须匹配旧归档的完成时间和
delivery hash。全部执行、输入、桥接、原生库与协议身份独立归档。
