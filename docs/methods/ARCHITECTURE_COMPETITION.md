# 固定H/plus的架构竞争：注册范围

基于`0eabd38`。本轮只回答：独立优化后，home/k2/k3怎样交换服务与lane、buffer、wire成本。
沿用统一Design、周期完整字执行、Service LP和CostModel，不继续工程重构，不释放placement。

## 公平条件

固定36C+36M、32 banks/M、256-bit/native slot、always-ready原生源、4GiB/C逻辑数据、
controller与物理HB可达性。各架构保留相同的**满载1 TB/s/C**，部分活动也保留每活动C≥1。
这是本轮服务SLO，不混入牺牲基本服务的方案。static A在每个工作负载分布的设计阶段冻结；
不同活动样本不得改A。逻辑对象相同，各架构物理条带可以不同。

两个固定synthetic workload分别评估，不混合评分：
1. 均匀random9：36中恰好9个活动，精确组合期望。
2. clustered9：6×6索引中所有16个不周期回绕的3×3窗口，等概率。
后者是明确给出的设计分布，不冒充未见真实trace泛化。另交叉评估两个分布选出的冻结布局。

## 本轮可证的设计族

- home：所有数据本地。SLO迫使256-bit完整服务，direct是本模型最低存储实现。
- k2：每bank保留home+一个shared；分别比较(2,3)、(1,4)、(1,2,3,4)均衡方向分组。
  每组bank数相同，分组由最小线长指派精确求解。真实边缘缺路保留本地。
  每条可交换边均匀互换对象内条带，比例由各自endpoint能力优化。
- k3：每bank保留home+两个相反shared，比较(2,3)/(1,4)。在允许图上分别求
  最大权匹配与最大基数下最大权匹配，允许未匹配compute保持home。权重是指定活动
  分布中的互斥活动概率；匹配在该图/目标下精确求解。

所有角色位宽从32至256、步长32。两个相反shared等宽，同类bank共用角色实现。
always-ready单口D1能力为1/ceil(256/w)，D2可以补齐跨字尾部至w/256；若无增益则
删除D2选项。更深深度不能超过位宽上界，本轮不做深FIFO扫描。加入所有结构的256 direct。

对每个角色实现先测qH、qS，反推λ=qH/(qH+qS)。单个compute的独占服务上界为qH+qS；
比例改变不会改变本轮主要三个硬件成本。如果该比例的固定平衡发起序列实现满载1且独占
达到上界，就完成该实现的比例优化。达不到则显式记为未闭合，不能宣称其最优。

k2边缘private bank和k3未匹配client迫使home具备原生全速，否则不满足满载SLO。
对有增益的k2 compute，每个必需bank必须交换正比例，因此不能通过删掉某个数据依赖
免费减少活跃邻居事件。当前固定配额构造在有活跃共享邻居时兑现1、全部相关邻居空闲时
兑现独占速率。对此构造的均值用实际所有者邻域精确计算，最终由统一执行/LP复核。

最优性仅覆盖这些共享结构、方向分组、同角色实现和互惠条带族。没有证明任意非均匀bank
模板、非互惠多来源A、任意请求顺序或整个fabric的全局最优。

## 运行与输出

先缓存小端点周期见证，并由达到上界的构造缩小配置集合；公共成本模型计算全部合法配置。
用已验证的结构活动系数筛选Pareto，保留生成、SLO淘汰和未闭合计数。对所有不同前沿设计
接回公共Evaluator，逐一验证random9精确均值、全部16个cluster窗口、full、single、one_pair、
一个注册random9样本和first9的LP；同时核对瞬时聚合容量及固定字节资源。

主要前沿：最大平均服务、最小export_lane_bits、endpoint_storage_bits、access_wire_bit_mm。
附加账本保留pipeline、控制、selector、HB，另报扩展成本前沿。主模型serializer在bank端；
port端序列化只作成本边界敏感性，不把未知本地接线、控制代理换算成面积/能耗。

输出每结构自己的前沿、全局前沿、相同lane/buffer/wire预算盒内的最佳实现、相同服务目标
的成本选择，以及random/cluster选择的交叉评估。不能只报无wire预算时最高TB/s。
