# 分开计费TX、HB在途beat和RX重组状态

2026-10-08。独立于cohort回放，不改变其整字预留合同，不修改RTL。

当前RTL的cse_fifo原生ready只取决于当前word count<depth；packetizer可观察同周期
新到字；TX held beat是独立寄存器。RX消耗旧完整字后为一个满宽beat预留空间，
容量为256+W−gcd(256,W)。本计数模型沿用这些边界，但没有证明payload/RTL周期等价。

候选链路在TX held beat与RX之间增加L级FIFO。每级的上游ready只依赖本级时钟沿前
是否有空位，不沿所有级组合传播，也不依赖本周期将发生的pop。每级保存一个或两个beat。
计入完整payload存储；beat有效单位、有效位/计数、选择逻辑、线与驱动另计，尚无物理标定。

注册检查W/D=(128/1,160/2,192/2,256/1)，L=0/1/2/4，比较每级1、2个beat。
另检查停顿周期(0)、(1,0)、(1,1,1,1,0,0,0,0)、31停/17行。
每个时钟沿检查256-bit字/32-bit单位守恒、source/held/link/RX容量，
寻找包含sink相位的重复状态，以整个周期的完整字数计吞吐。

制造成本需按实际保留的方向计费：configurable的Shared TX只有一份，但两个物理方向
的HB流水和RX仍可能都需要保留。某实例未使用该方向不自动删除模板中的寄存器与线。
同宽duplicated/configurable必须使用相同链路/接收合同。

该候选的下一步是与RTL逐拍对照、接入真实请求/原生返回预留，再做局部时序和成本验证。
计数周期不等于整片任务时间，也不能证明长线ready时序已经闭合。
