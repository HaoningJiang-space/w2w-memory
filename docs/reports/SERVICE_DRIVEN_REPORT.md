# Memory Fabric：服务驱动布局与 Gurobi 整数综合

**这一轮找到的有用结构变化，是把固定数据的共享依赖收敛到一个平衡伙伴；
训练吞吐优化本身则出现了明显过拟合。** 新增了可核验的 Gurobi ILP，
但最优性只覆盖限定的完整 bank 配对结构，不能解释成整个 fabric 已全局最优。

## LP、ILP 和 Gurobi 分别做什么

| 问题 | 数学类型 | 本轮实现 |
|---|---|---|
| 冻结 hardware 和 data shares，计算服务率和 routing flow | 连续 LP | HiGHS |
| 同时更新连续字节比例 a 和服务率 r | 原问题含 a×r；逐次线性化是启发式 | 每次 LP 提案均由原服务 LP 重新核验 |
| 在完整 bank、等分数据、互不重叠的配对结构中选择 pairs、重复 bank-port edges、32-bit lanes | 纯 ILP | Gurobi 13.0.3，225 个整数变量，最终模型 723 条约束 |

两个整数预算实例的吞吐目标与成本第二阶段都返回 OPTIMAL、gap=0；还用独立
NetworkX matching 枚举两个方向族，再用 HiGHS 固定数据服务核对最优值。
96-edge 预算下，训练增益目标为 **0.449074074**，bound 相同；总服务为 **1.449074074**。
最优解是方向 (2,3)、18 对 compute、96 条重复 bank-port 连接、
端口宽度 `[8000,0,8000,8000,0]` bit @ 1 GHz，总配置 3 TB/s。

64-edge 预算在这个 ILP 族内只能选 home-only，目标为 0。
**这不是证明 k=2 无效**：旧的“每组 banks 分给不同伙伴”的 k=2 构造本来就不在
“一个 compute 的完整 bank 流只配一个伙伴”的 ILP 设计族中。
同样，本轮 Gurobi 解与 (2,3) 最大基数配对基线相同，没有超过该强基线。

服务器现有许可证能运行上述模型；2101-variable 探针返回限规模错误 10010。
用户 Downloads 的另一份学术许可证在 eex005 返回 HostID mismatch（10009），
没有全局激活，临时服务器副本已删除。没有向 Git 写入任何密钥。

## 新结构的收益来自哪里

旧 k=2 把 bank groups 分给两个方向，每个对象的数据同时依赖多个伙伴。
即便其余资源空闲，一个共同活动的必经伙伴也可能把整个固定请求流限制在基线。
新的 k=3 每个 bank 接 home 和两个相反方向；静态布局再只选一个互反伙伴，
每个对象一半在 home、一半在 peer，完整覆盖两边的 32 banks。
两人都活动时各 1；只有一个活动时为 2。数据没有复制或运行时移动。

两个构造使用相同的 H/plus 几何和 (2,3) 端口方向；变化是 bank exposure、
通道宽度和静态布局，**不是提高 reticle-level radix**。
(2,3) 可以匹配全部 36 个 compute；(1,4) 只能匹配 30 个。
硬件模板仍然在所有 reticle 上重复，配对关系属于离线数据布局。

对所有等概率 9-of-36 活动集合，可以直接算出总体期望，不依赖挑选 seeds：

| 构造 | 平均服务 TB/s/active | 相对 home 的增益 |
|---|---:|---:|
| 旧 k=2、两个共享方向 | 1.327731 | 32.77% |
| k=3、(1,4) 最大基数配对 | 1.642857 | 64.29% |
| k=3、(2,3) 完整配对 | 1.771429 | 77.14% |

配对 t 个客户端、恰好 a 个活动时，期望为
`1 + (t/36)*(36-a)/35`。完整配对的公共完成率也不再永远等于 1：
没有任何一对同时活动时为 2，否则为 1。a=9 时，前者概率为
`2^9 * C(18,9) / C(36,9) = 0.264421`，因此平均公共完成带宽为 **1.264421**。
平均等工作量流体阶段时长为基线的 **0.867790**；不能取平均带宽的倒数充当平均时长。
这些是模型内解析量，尚不是应用加速。

## 成本与通道消融

| 结构 | Bank-port edges | Wire proxy / memory reticle | 配置 HB | Shared fan-in |
|---|---:|---:|---:|---|
| Home-only | 32 | 472.0 mm | 1 TB/s | — |
| 旧 k=2 对向分组 | 64 | 943.6 mm | 2 TB/s | 16 / 16 |
| k=3 完整配对 | 96 | 1852.2 mm | 3 TB/s | 32 / 32 |
| 完整五端口、相同 (2,3) 配对布局 | 160 | 3232.4 mm | 4 TB/s | 32 / 32 / 32 / 32 |

k=3 比旧 k=2 多 50% connections、约 96.3% wire proxy 和 50% 配置带宽。
因此不是等成本的 1.328→1.771 胜利。相对于完整五端口的**同一配对布局**，
它去掉 40% connections 和约 42.7% wire，同时保留其服务；不代表达到完整五端口
任意布局的最优性能，也不是达到任意数据重映射 oracle。

补充的解释性消融没有参与设计选择：保持 k=3 配对布局，但把两条共享方向各从
1 TB/s 缩到 0.5 TB/s，服务回到 1。因为每个流的半数字节必须过共享端口，
`0.5*r <= 0.5` 直接限制 `r <= 1`。保持 k=3/3 TB/s 但用 home-only 数据也只有 1。
反过来，给旧 k=2 更多端口宽度，不会增加每个 16-bank group 的总服务能力。
这些控制检查了全部 36 个单活动客户端、满载可行性和训练场景。

所有候选都接受相同的保守端口宽度裁剪，依据可经过端口的 banks 容量去除不可用宽度。
这修正了上一轮用满 4 TB/s 的冗余配置，不作为算法创新。
实际 bank 输出为 256 bit @ 1 GHz，聚合端口并行宽度显式受限；buffer/register、
selection-input 和 bit-mm 代理在 JSON 中列出。没有 PDK、拥塞、timing 或芯片 PPA 结论。

## 直接优化训练吞吐，是否比结构化基线更好

| 0.9 服务档 | 训练：原始 → 优化 | 验证：原始 → 优化 |
|---|---:|---:|
| X full | 1.0000 → 1.0661 | 1.0000 → 1.0502 |
| XY full | 1.0000 → 1.2011 | 1.0000 → 1.0872 |
| k2 (1,4) | 1.0889 → 1.1175 | 1.0847 → 1.0793 |
| k2 (2,3) | 1.1377 → 1.1598 | 1.0799 → 1.0699 |
| k2 四方向 | 1.0424 → 1.0885 | 1.0336 → 1.0042 |
| full5 pairs | 1.4491 → 1.4940 | 1.3981 → 1.3094 |

X/XY 在 0.9 服务档确实获得验证集收益；严格 1.0 档仍回到本地化。
但是三个 k=2 构造和 full5 的训练改进没有转化成验证改进。
新增两组非均匀 exposure 各用 68 edges、1027.8 mm，验证均值也未超过相应预算下
的结构化基线。不能把“优化器提高了训练目标”写成已证实的算法性能贡献。
X/XY 控制用了 128 edges / 2360 mm，不能将它们当成 64-edge 的等成本设计。

验证集在两个服务档均选择：64/1000 与 72/1400 预算使用旧 k=2 (1,4)；
96/2000 和 160/3600 预算使用 k=3 (2,3) ILP 解。SLP 没有成为本轮预算胜者。
这些结论只针对注册候选集合，不是全设计空间 Pareto 最优性证明。

## 保留的算法选项（当前暂不推进）

当前最可靠的发现是：**相同几何下，增加某些 bank exposure 并正确配置通道，
可以让静态数据从“同时依赖多个伙伴”改成“依赖一个完整伙伴”，显著改变 pooling。**
这比单独扩大 reticle degree 更具体，但现有成本还不足以支持“很便宜”或“回收大部分
全局闲置带宽”的判断。1.771 对全局 4 TB/s/active 上界只回收约 25.7% 的潜在增益。

按最新研究节奏，当前先做 [bank→HB 物理边界审查](../background/BANK_HB_PHYSICAL_BOUNDARY.md)，
并进行最小端点容量对照，不扩大 DSE。厘清真实端点与交换能力之后，可以将 pair、bank-group exchange、home
等有限布局组成候选库，用 Gurobi
做真正的 MILP 参照：共享硬件变量是整数，流量与服务率仍连续；布局选择 z 为二值时，
`r*z` 可以在 controller cap=4 的已知界内精确线性化。
任意连续 a 与 r 的乘积则仍是非凸项，不能因为换成 Gurobi 就称作 ILP。
当前小训练集的过拟合应通过更丰富的训练分布与稳健目标研究，不在本测试集上继续调参。
这保留非均匀 edges/width、有限服务退步和静态 co-design 自由度。

H/plus、页内交错和 bank sharing 本身仍不申报创新；SiloBreaker 的全文方法重合
尚未排除。研究对象仍是 repeated-reticle 几何下 bank exposure、HB 通道与数据驻留
的联合设计，没有扩展到 thermal、yield、PDN、runtime migration 或 DRAM timing。
