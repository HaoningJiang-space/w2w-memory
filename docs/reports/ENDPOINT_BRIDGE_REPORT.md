# Endpoint → bank → wafer：固定配对上的首次闭环

研究目标没有改变。本轮把新的出口约束与完整字执行接入旧的 wafer service，
只使用同一 H/plus k3、18 对、固定 half-home/half-peer 数据；没有重新选图或数据。
方法和适用边界见 [ENDPOINT_BRIDGE_METHOD.md](../methods/ENDPOINT_BRIDGE_METHOD.md)。

## 已补上的两处连接

1. `EndpointFixedService` 复用旧 `FixedService` 的全部固定字节等式及物理容量，
   为 serial 增加 `sum f/lambda <= 1` 公共路径时间约束。F、serial、elastic
   不再是独立 probe，也不再只换名字而共享同一容量矩阵。
2. `execute` 实际维护完整字、剩余位数、有限队列和反压。执行完成率以路径容量
   接入同一 wafer LP，并构造独立原始流量证书。旧代码和旧报告语义不变。

有限执行使用 256-bit 完整字、每原生服务时隙最多产生一个字；出口每时隙发送
64/128/192/256 bits。D 表示每出口的完整字存储位置，包含正在串行发送的字。
D=0 是带一个共享 holding register 的 direct 模式，绝不是零存储的理想接口。
全部参数均为明确的数字模型假设，尚未按 DRAM 工艺或命令时序校准。

## 主要结果：哪些旧收益能兑现，哪些受出口限制

单位 TB/s；使用轮询仲裁。单独活动列是一个 C，满载列是所有 36 个 C 的人均。

| 每出口峰值 / bank 原生服务 | 实现 | 单个 C 活动 | 满载每 C |
|---:|---|---:|---:|
| 1.00 | direct，一个共享字寄存器 | 2.000 | 1.000 |
| 1.00 | buffered，D=1 | 2.000 | 1.000 |
| 0.50 | direct | 1.000 | 0.500 |
| 0.50 | buffered，D=1 | 1.000 | 1.000 |
| 0.75 | direct | 1.000 | 0.500 |
| 0.75 | buffered，D=1 | 1.000 | 1.000 |
| 0.75 | buffered，D=2 | 1.500 | 1.000 |

**足宽出口不一定需要独立 FIFO 才能保留旧结果。** alpha=1 时，轮流发送完整字
已经足够在这个模型内兑现 full-pair 的单活跃 2、满载 1。不能预设加上真实过程
以后性能一定下降，也不能把 FIFO 当作所有 pooling 的必要条件。

**窄出口的并行排空确实可以恢复服务。** alpha=0.5 时，两个有需求出口各有一份
完整字存储即可交替接收并独立排空；满载从 0.5 恢复到 1。但单个出口仍只有
0.5 bank 服务，孤立活跃 C 的两条路径合计只有 1，因此没有额外 pooling gain。

**alpha=0.75 的 direct 执行值低于其流体包络。** 256-bit 字经过 192-bit/slot
出口，需要两个时隙；此 direct 模型不允许中途发起下一个字，尾部 lane 被浪费。
D=1 也无法对单一出口跨字连续填满，D=2 才能让 192-bit lane 持续利用。
这是明确的寄存器/发起时序选择，不是所有 192-bit 电路必然只有一半效率。
允许跨字打包或其他时序会改变结果，不能推广为 DRAM 物理定律。

F 对本重复三出口模板固定分给每口 1/3，所选 pair 只用其中两口，因此 alpha≥1/3
时单活跃与满载均为 2/3。它没有按 reticle 实例免费重分配第三口的份额；
这个结果也不是对所有 private/partitioned baseline 的排名。

## 队列深度何时真的改变服务

两个忙出口，alpha=0.5，每个目的端连续八个字，严格保持发起目的序列：

| 每出口 D | 实际 bank 总服务 / mu | 8192 观测时隙中的反压时隙 |
|---:|---:|---:|
| 0（direct） | 0.500000 | 4096 |
| 1 | 0.533325 | 3823 |
| 2 | 0.615356 | 3151 |
| 8 | 1.000000 | 0 |

同样 alpha 和 D，允许轮询绕过满队列时，D=1 即可达到 1。说明需要同时给定
出口位宽、队列容量、发起规则和地址/请求顺序，不能只填一个 `buffer_depth`。
有序突发只是受控对照，不声称真实 DRAM 必须采用这个较弱仲裁策略。

## 随机总体与单个测试集合分开

本轮 random9 固定集合中有 5 个客户端的伙伴空闲，4 个客户端成对活跃。
足宽时其均值为 1+5/9=1.555556，这不是此前精确总体均值下降。
在均匀 9-of-36 总体中，给定 C 活动，其伙伴空闲概率仍是 27/35。
令执行模型中孤立/双活跃速率分别为 r_single、r_pair，则精确总体期望为：

    E[r | active] = (27*r_single + 8*r_pair)/35.

足宽 direct/buffered 都恢复 1.771429；alpha=0.75、轮询、D=2 为 1.385714；
alpha=0.5、轮询、D≥1 为 1。这些是该固定数字模型的解析人口期望，仍不是应用加速。

## 正确性与范围

- eex005 源提交 `af999ea`，64 条有限执行轨迹、160 组 wafer 对照。
- 每条轨迹 1024 时隙 warmup + 8192 观测时隙，逐时隙核对 word/bit 守恒和队列界。
- 160 组均重新求吞吐、公共完成及保底可行性，保留不可行结论。
- 全部结果使用同一个静态布局 hash；无迁移、复制、runtime 改图或训练选择。
- 独立按每对活跃人数和执行完成字数重算 160 组均值/公共速率及三个 LP 包络，
  最大误差 1.11e-16。复核脚本：`w2w/analysis/analyze_endpoint_bridge.py`。
- 四个预先指定案例将观测时间加倍，测得总吞吐差均为 0。
- 本地 23 项相关测试通过；服务器新执行/合同的 11 项测试通过。

这里并没有运行一个通用的全 wafer 队列模拟器。使用本配对结构的特殊性，
每个 memory 的 32 个 bank 可重复同一执行，所选各物理端口的瞬时发送不超过
其容量，再用固定字节 LP 验证组合。复杂布局里的共享路径、路由和额外队列
不能直接沿用这个分解；需要进一步显式处理。

## 成本与下一步边界

仍为 96 bank-port 连接；只改变数据输出宽度和存储。每 memory 的 endpoint
存储：direct 8192 bit；D=1/2/8 分别为 24576/49152/196608 bit。
重复模板的第三个出口即使当前布局不用，仍计入硬件。输出连线位数随 alpha 改变，
HB 端口总预算保持不变。上述不含控制、tag、跨时钟、额外 pipeline 或物理 PPA；
旧 cost 字典仅留作来源记录，不能重复累加旧抽象 FIFO 再宣称完整成本。

这轮闭环支持的结论是：**原先的共享收益可以追溯到具体出口的发起、存储和排空
条件；某些数字实现能达到旧包络，另一些会明显达不到。** 研究目标仍是整片
memory service fabric，后续应先约束这些数字实现的可实现成本，而非另开 FIFO 题目。
