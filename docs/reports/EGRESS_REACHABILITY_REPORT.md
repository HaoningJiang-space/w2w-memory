# 地址权限不能产生物理路径

在源码 `8b27f7b` 的现有 H/plus full-pair 实例中，146 个 C–M 邻接各有一条物理 edge；固定布局使用的 2,304 个 C–bank 关系各只有一条路线。

因此，仅把地址权限 R 改成“允许经任意出口返回”，并不会使该 compute 能接收原本连到伙伴的另一出口。物理接收关系 Y 必须独立满足。

归一化的两 memory、两 compute 模型保持 A_cm=.5，每 memory 两出口各 .5：

| 构造 | 单活动服务 | 两者活动时每 C 服务 |
|---|---:|---:|
| 现有物理 Y，唯一出口或放开 R | 1 | 1 |
| 现有 Y，强制每份数据两出口各一半 | 不可行 | 不可行 |
| 放松 Y、两出口都能到达同一 C，静态交错 | 2 | 1 |

第二行的 LP 最大速率为零，表示必要字节没有合法路径，不能描述为可制造方案的普通性能退化。第三行改变了物理接收关系，只是聚合能力参考，不是同一 H/plus 上的实现结果。再施加共享串行通路约束，第三行单活动服务也会回到 1。

这不意味着必须增加 reticle overlap：一个更宽的合法单出口，或明确建模并计费的内部汇聚通路，也可能提供能力。但不能把它藏在 R 的变化里。
