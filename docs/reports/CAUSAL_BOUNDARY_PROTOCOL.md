# Causal boundary census and minimal native callback gate

P0 separates observed interface progress, resource-state projection changes,
compute-only service and admission retries in three fixed small cases: the
accepted stable and transport inputs, plus two independent contexts on c2/c3
reading the same 8 KiB object from m0_0 (reuse 256). It uses the existing
integer-ps time driver and native tools. Diagnostic instrumentation must not be
reported as a performance run. Every diagnostic result passes native system,
request control and command audits. Quiet observations are not safe horizons.

P1 is limited to one funded contiguous-prefix streaming context, native BookSim
idle with no local/receive events, no pending request issue or memory admission,
and no queued domain/Gateway service. Active array requests are required. Known
frontend events, task release, prefix exhaustion and deadline cap the horizon.
The native bridge may execute ordinary Ramulator ticks only until its first
callback or this cap. Completed atoms are held for delivery at that exact system
boundary; no request may be submitted while a prefetched completion is waiting.
NoC, routing, finite resource rules and internal DRAM/refresh service are unchanged.

Compute service inside that certified interval is represented by the existing
interactive rule. Full events expand at their original times; task tails and
all external callbacks use the ordinary phases. The original kernel remains the
default. No arbitrary active BookSim lookahead, NI progress batching, Gateway
batching or whole-application replacement is part of this gate.

Same-policy off/interactive/coordinated comparisons use the same binaries and
Full evidence. Stable repeats three times, transport and concurrent once.
The new bridge's ordinary advance also cross-checks the old accepted stable
record. Accuracy requires all physical records, command/time/address and endpoint
fingerprints, task clocks and final drain equal. An independent checker reconstructs
the omitted clock union and each skipped compute service; actual iterations,
callback/call counts, Python CPU and full worker times are reported separately.

If the restrictive active-array guard has zero coverage, or observed feedback
leaves little safe time, report that result. Forty-percent fewer wakeups is a
research target, not a gate weakened by counting already accepted quiescent
skips. Do not manufacture native delays or change clocks/bandwidth to pass.
P2 or a larger matrix requires evidence of a useful coordination boundary.
